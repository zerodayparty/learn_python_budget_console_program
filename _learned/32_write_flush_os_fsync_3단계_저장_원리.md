# 🟩 파이썬 파일 저장의 3단계: write(), flush(), os.fsync()

## 🟢 주요 영단어 풀네임 및 용어 정리

- 용어 풀네임 목록
    - `write` = Write (쓰다, 기록하다 / 파이썬 앱 내부 임시 바구니에 글자를 적음)
    - `flush` = Flush (물을 쏟아내다 / 파이썬 바구니를 비워 운영체제(OS)에게 넘김)
    - `os` = Operating System (운영체제 / Mac, Windows 등 컴퓨터 하드웨어를 총괄 제어하는 시스템)
    - `fsync` = File Synchronize (파일 동기화 / 운영체제가 쥐고 있는 데이터를 물리 디스크에 강제 동기화함)
    - `fileno` = File Number / File Descriptor (파일 번호표 / 운영체제가 열려있는 파일을 식별하기 위한 정수 번호)
    - `system call` = System Call (시스템 호출 / 프로그램이 운영체제에게 하드웨어 제어를 부탁하는 직접 명령)

<br><br>

## 🟢 3단계 데이터 저장 흐름도

컴퓨터에서 글자를 저장할 때 데이터는 총 3개의 관문을 거쳐 물리적인 디스크(SSD/HDD)에 도달함.

```
[1단계: 파이썬 프로그램]
        │
        ▼  write() 실행
[2단계: 파이썬 앱 버퍼 (내부 임시 바구니)]
        │
        ▼  flush() 실행
[3단계: 운영체제(OS) 커널 캐시 (OS 임시 보관소)]
        │
        ▼  os.fsync() 실행
[최종: 물리 저장장치 (진짜 SSD / 하드디스크 칩)]
```

<br><br>

## 🟢 write vs flush vs os.fsync 3단 비교

| 구분 | 1단계: `write()` | 2단계: `flush()` | 3단계: `os.fsync()` |
| :--- | :--- | :--- | :--- |
| **명령 주체** | 파이썬 파일 객체 (`f.write`) | 파이썬 파일 객체 (`f.flush`) | 운영체제 모듈 (`os.fsync`) |
| **데이터 이동** | 코드 $\rightarrow$ **파이썬 메모리 버퍼** | 파이썬 버퍼 $\rightarrow$ **운영체제(OS) 캐시** | 운영체제 캐시 $\rightarrow$ **진짜 물리 디스크** |
| **정전 시 위험** | 컴퓨터 꺼지면 **100% 증발** | 컴퓨터 꺼지면 **100% 증발** (OS가 아직 디스크 안 썼음) | 컴퓨터 꺼져도 **100% 영구 보존** |
| **쉬운 비유** | 내 책상 **개인 우편함**에 넣기 | 개인 우편함 비워서 **우체국 트럭**에 싣기 | 우체국 트럭에게 **"지금 즉시 은행 금고에 넣고 와!"** 명령 |
| **수행 속도** | 상상 초월로 가장 빠름 | 매우 빠름 | 디스크를 직접 긁으므로 가장 느림 |

<br><br>

## 🟢 왜 flush()만으로 안심할 수 없을까?

- 많은 사람들이 `flush()`를 하면 하드디스크에 바로 적힌다고 오해함.
- 하지만 `flush()`는 **파이썬의 손을 떠나 "운영체제(Mac OS, Windows)"에게 데이터를 건네준 것뿐**임.
- 운영체제(OS) 역시 컴퓨터 속도를 빠르게 유지하기 위해, 자기가 받은 데이터를 바로 SSD에 쓰지 않고 자기만의 임시 보관소(OS 페이지 캐시)에 쥐고 있음.
- **최악의 시나리오**:
    - `flush()`를 호출한 직후 컴퓨터 전원 플러그가 뽑히면?
    - 운영체제가 아직 디스크에 쓰지 못하고 쥐고 있던 데이터는 그대로 날아가 버림!
- **`os.fsync()`의 등장**:
    - "운영체제야, 쥐고 있지 말고 **지금 당장 0.001초도 지체 없이 물리 SSD 플래시 메모리에 박아 넣어라!**" 하고 하드웨어를 강제 제어하는 명령임.

<br><br>

## 🟢 3단계를 함께 사용하는 완벽한 실습 코드

```python
# 운영체제 하드웨어 제어 도구 상자인 os 모듈을 불러옴
import os

# 파이썬 기본 open 함수로 'safe_data.txt' 파일을 쓰기 모드로 엶
with open("safe_data.txt", "w", encoding="utf-8") as f:
    # [1단계: write] 글자를 파이썬 프로그램 내부 임시 버퍼에 적음
    f.write("금고에 영원히 보관해야 할 비밀 장부 내용")
    
    # [2단계: flush] 파이썬 임시 버퍼를 비워 운영체제(OS)에게 넘김
    f.flush()
    
    # [3단계: os.fsync] 운영체제가 쥐고 있는 캐시 데이터를 진짜 물리 SSD/하드디스크에 강제로 영구 기록함
    # (f.fileno()는 운영체제가 이 파일을 구별하기 위해 붙여둔 고유 번호표임)
    os.fsync(f.fileno())

# 4. with 블록이 끝나면 파일이 안전하게 닫힘
```

<br><br>

## 🟢 실제 개발에서는 언제 쓸까?

- **일반적인 프로그램 (가계부, 텍스트 편집기 등)**:
    - `os.fsync()`까지 쓰면 디스크를 매번 강제로 돌려야 해서 프로그램이 느려짐.
    - 보통 `with` 문이 닫힐 때 자동으로 실행되는 `flush()`와 `close()`만으로도 99.9% 충분함.
- **금융 시스템, 데이터베이스(SQLite, MySQL, 결제 시스템)**:
    - "전원이 갑자기 나가도 고객 돈 100원은 절대 사라지면 안 된다!"
    - 이런 극도로 중요한 트랜잭션 기록에는 반드시 `write()` $\rightarrow$ `flush()` $\rightarrow$ `os.fsync()` 3단계를 모두 거쳐 물리 디스크 저장을 보장함.

## 🟢 타인에게 설명할 때의 핵심 한마디

- "`write()`는 **내 우편함**에 넣는 것, `flush()`는 **우체국 트럭**에 싣는 것, `os.fsync()`는 **트럭을 출발시켜 금고에 영구 보관**하는 것이다."
- "`flush()`는 파이썬에서 OS로 넘기는 것이고, `os.fsync()`는 OS에서 진짜 하드디스크 칩으로 집어넣는 것이다."
