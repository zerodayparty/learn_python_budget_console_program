# 🟩 파이썬 골뱅이(@) 데코레이터 완벽 해설  

## 🟢 주요 영단어 풀네임 정리  

- 용어 풀네임 목록  
    - Decorator = Decorate(장식하다) + or(~하는 도구) (기존 코드를 건드리지 않고 기능을 덧붙여주는 장식자)  
    - dataclass = Data Class (데이터 보관용 클래스를 자동으로 만들어주는 파이썬 도구)  
    - frozen = Freeze(얼리다)의 과거분사 (데이터가 생성된 후 절대 수정되지 못하도록 얼려버림)  
    - classmethod = Class Method (클래스 틀 자체가 직접 실행하는 함수)  
    - property = Property (속성, 재산 / 함수를 마치 변수처럼 괄호 없이 읽게 해주는 도구)  
    - cls = Class (클래스 틀 자기 자신을 가리키는 이름)  
    - self = Self (클래스 틀로 찍어낸 실제 객체 자기 자신)  
    - dict = Dictionary (키와 값으로 짝지어 데이터를 담는 파이썬 사전형 자료구조)  
    - JSON = JavaScript Object Notation (데이터를 주고받을 때 사용하는 표준 글자 형식)  
    - ID = Identifier (고유 식별자, 중복되지 않는 고유 번호)  
    - str = String (문자열, 글자 데이터)  
    - int = Integer (정수, 소수점이 없는 숫자)  
    - bool = Boolean (참 True 또는 거짓 False만 가지는 논리값)  
    - def = Define (함수를 정의하다)  

<br><br>

## 🟢 골뱅이(@)의 정체: 데코레이터(Decorator)  

### 🟡 1. 데코레이터란 무엇인가?  
- 골뱅이(`@`) 기호는 파이썬에서 **데코레이터(Decorator)**라고 부름.  
- 단어 그대로 **장식자(꾸며주는 도구)**라는 뜻임.  
- 현실 세계 비유:  
    - 맨몸의 스마트폰 위에 **방수 케이스(스티커/모자)**를 씌우면 내부 부품을 개조하지 않아도 **방수 초능력**이 생김.  
    - 마찬가지로 함수나 클래스 머리 위에 `@데코레이터`라는 모자를 씌우면, 원래 코드를 수정하지 않고도 **새로운 초능력(추가 기능)**이 장착됨.  

<br><br>

### 🟡 2. 파이썬 내부 동작 원리  
- 파이썬은 머리 위에 `@`가 붙은 함수나 클래스를 만나면 아래와 같이 포장지로 감싸서 바꿔치기함.  

```python
# 장식 모자를 정의하는 함수다.  
def 마법_모자(원래_함수):  
    # 원래 함수를 감싸서 새로운 행동을 덧붙이는 포장지 함수다.  
    def 포장지():  
        # 원래 함수가 실행되기 전에 안내 문구를 출력한다.  
        print("마법 시작!")  
        # 전달받은 원래 함수를 실행한다.  
        원래_함수()  
        # 원래 함수가 끝난 뒤 마무리 문구를 출력한다.  
        print("마법 끝!")  
    # 포장이 끝난 새 함수를 돌려준다.  
    return 포장지  

# 인사 함수 머리 위에 마법 모자 데코레이터를 씌운다.  
@마법_모자  
# 사용자에게 인사를 건네는 단순한 함수를 만든다.  
def 인사():  
    # 실제 인사말을 화면에 출력한다.  
    print("반갑습니다.")  

# 인사 함수를 실행하면 마법 시작과 마법 끝이 자동으로 함께 실행된다.  
인사()  
```

- 위 코드에서 `@마법_모자`를 쓰는 것은 내부적으로 `인사 = 마법_모자(인사)`를 실행한 것과 완전히 똑같음.

## 🟢 models.py에 등장하는 3가지 데코레이터 상세 분석  

`budget_app/models.py` 파일에는 총 3가지 데코레이터가 등장함.  

### 🟡 1. @dataclass(frozen=True)  
- 등장 위치: `Transaction` 클래스 위(17번째 줄), `MonthlySummary` 클래스 위(64번째 줄)  

```python
# 만든 뒤 값이 몰래 바뀌지 않는 거래 데이터 클래스를 선언한다.  
@dataclass(frozen=True)  
# 거래 한 건이 반드시 가져야 할 값을 묶은 클래스다.  
class Transaction:  
    # 각 거래를 구별하는 고유 번호다.  
    id: str  
    # 수입인지 지출인지 종류를 저장한다.  
    type: str  
    # 거래 날짜를 YYYY-MM-DD 형식으로 저장한다.  
    date: str  
    # 거래 금액을 0보다 큰 숫자로 저장한다.  
    amount: int  
    # 카테고리 이름을 저장한다.  
    category: str  
    # 메모 내용을 저장한다.  
    memo: str  
    # 태그 목록을 저장한다.  
    tags: List[str]  
```

- **풀네임**: Data Class (데이터 클래스)  
- **하는 일 (역할)**:  
    - 일반 파이썬 클래스는 데이터를 저장하려면 생성자 함수(`__init__`), 출력용 함수(`__repr__`), 비교 함수(`__eq__`)를 수십 줄씩 손수 작성해야 함.  
    - `@dataclass`를 붙이면 파이썬이 이 필수 함수들을 0.001초 만에 **자동으로 생성**해 줌.  
- **frozen=True 옵션의 의미**:  
    - `frozen`은 **얼어붙은(수정 불가능한)** 상태를 뜻함.  
    - 객체가 한 번 만들어지면 내부 값을 누구도 변경할 수 없게 단단히 얼려버림(불변성 보장).  
    - 만약 프로그램 중간에 누군가 `tx.amount = 9999999` 처럼 값을 위조하거나 바꾸려고 하면 파이썬이 에러(`FrozenInstanceError`)를 발생시켜 프로그램을 안전하게 보호함.  

<br><br>

### 🟡 2. @classmethod  
- 등장 위치: `Transaction` 클래스 내부의 `from_dict` 함수 위(38번째 줄)  

```python
    # 객체가 없어도 Transaction.from_dict 형태로 직접 호출할 수 있게 만든다.  
    @classmethod  
    # JSON 사전을 검사해서 거래 객체로 만들어 돌려주는 함수다.  
    def from_dict(cls, raw: Dict[str, Any]) -> "Transaction":  
        # 필수 항목 확인과 값 검사를 시도한다.  
        try:  
            # 필수 id 값을 공백을 제거한 문자열로 읽는다.  
            transaction_id = str(raw["id"]).strip()  
            # id가 비어 있는지 확인한다.  
            if not transaction_id:  
                # 비어 있으면 오류를 발생시킨다.  
                raise KeyError("id")  
            # 검사를 통과한 값으로 클래스 객체를 생성해서 돌려준다.  
            return cls(  
                # 식별자 번호를 전달한다.  
                id=transaction_id,  
                # 거래 종류를 검사하여 전달한다.  
                type=validate_transaction_type(str(raw["type"])),  
                # 거래 날짜를 검사하여 전달한다.  
                date=validate_date(str(raw["date"])),  
                # 거래 금액을 검사하여 전달한다.  
                amount=validate_amount(raw["amount"]),  
                # 카테고리를 검사하여 전달한다.  
                category=validate_category_name(str(raw["category"])),  
                # 메모가 없으면 빈 글자로 채운다.  
                memo=str(raw.get("memo") or ""),  
                # 태그가 없으면 빈 목록으로 채운다.  
                tags=normalize_tags(raw.get("tags", [])),  
            )  
        # 잘못된 데이터가 발견되면 잡아서 처리한다.  
        except (KeyError, TypeError, ValueError, ValidationError) as error:  
            # 오류 메시지를 준비한다.  
            message = "거래 저장 파일의 데이터 형식이 잘못되었다."  
            # 해결 힌트를 준비한다.  
            hint = "손상된 줄을 수정하거나 백업 파일로 복구한다."  
            # 원인과 힌트를 담은 파일 오류를 던진다.  
            raise DataFileError(message, hint) from error  
```

- **풀네임**: Class Method (클래스 메서드)  
- **일반 메서드와의 차이점**:  
    - 일반 함수: 첫 번째 인자로 `self`(이미 태어난 붕어빵 객체)를 받음. 즉, 먼저 객체를 만들어야만 부를 수 있음.  
    - `@classmethod`: 첫 번째 인자로 `self`가 아니라 `cls`(붕어빵 틀 그 자체, 즉 `Transaction` 클래스)를 받음.  
    - 따라서 객체를 아직 만들지 않은 상태에서도 `Transaction.from_dict(...)` 형태로 틀 이름을 통해 직접 부를 수 있음.  
- **하는 일 (역할)**:  
    - **대체 생성자(공장)** 역할을 함.  
    - 파일에 저장되어 있던 날것의 JSON 딕셔너리(`raw`) 데이터를 받아서 유효성 검사를 거친 뒤, 완벽한 `Transaction` 객체로 찍어내어 돌려줌.

### 🟡 3. @property  
- 등장 위치: `MonthlySummary` 클래스 내부의 `balance`, `budget_usage`, `is_over_budget` 함수 위(73, 77, 83번째 줄)  

```python
    # summary.balance처럼 소괄호 없이 변수처럼 읽을 수 있는 계산 기능으로 만든다.  
    @property  
    # 총수입에서 총지출을 뺀 잔액을 계산한다.  
    def balance(self) -> int:  
        # 수입 합계에서 지출 합계를 뺀 계산 결과를 돌려준다.  
        return self.total_income - self.total_expense  

    # summary.budget_usage처럼 변수처럼 읽을 수 있는 계산 기능으로 만든다.  
    @property  
    # 예산 대비 지출 비율(백분율)을 계산한다.  
    def budget_usage(self) -> Optional[float]:  
        # 예산이 아예 설정되어 있지 않은지 검사한다.  
        if self.budget is None:  
            # 계산할 예산이 없으므로 비어있다는 뜻의 None을 돌려준다.  
            return None  
        # 지출을 예산으로 나누고 100을 곱해 퍼센트로 돌려준다.  
        return self.total_expense / self.budget * 100  

    # summary.is_over_budget처럼 변수처럼 읽을 수 있는 계산 기능으로 만든다.  
    @property  
    # 지출이 예산을 초과했는지 참/거짓으로 계산한다.  
    def is_over_budget(self) -> bool:  
        # 예산이 존재하면서 지출이 예산보다 큰 경우에만 참을 돌려준다.  
        return self.budget is not None and self.total_expense > self.budget  
```

- **풀네임**: Property (속성, 고유 성질)  
- **하는 일 (역할)**:  
    - 원래 함수는 실행할 때 `summary.balance()` 처럼 끝에 **소괄호 `()`**를 붙여야 함.  
    - 하지만 `@property`를 붙이면 소괄호 없이 `summary.balance` 처럼 **일반 변수(속성)**처럼 바로 꺼내 쓸 수 있게 됨.  
- **왜 일반 변수로 저장하지 않고 @property 함수로 만들었는가?**:  
    - **이유 1: 실시간 자동 계산**: 잔액이나 예산 초과 여부는 고정된 값이 아니라 수입이나 지출이 바뀔 때마다 실시간으로 계산되어야 하는 값이기 때문임.  
    - **이유 2: 읽기 전용 보안(자물쇠)**: 외부에서 `summary.balance = 1000000` 처럼 잔액을 조작하려 하면 파이썬이 `AttributeError`(수정 불가 오류)를 내뿜으며 조작을 차단함.

## 🟢 데코레이터 3종 핵심 비교표  

| 데코레이터 이름 | 소속 모듈 | 붙이는 위치 | 핵심 역할 | 실생활 비유 |  
| :--- | :--- | :--- | :--- | :--- |
| `@dataclass(frozen=True)` | `dataclasses` | 클래스 머리 위 | 생성자/비교 함수 자동 생성 및 값 수정 방지(불변) | 단단한 밀봉 자물쇠 상자 |  
| `@classmethod` | 파이썬 내장(기본) | 클래스 안 함수 위 | 객체 없이 클래스 이름으로 직접 호출하는 객체 생성 공장 | 붕어빵을 굽는 기계 버튼 |  
| `@property` | 파이썬 내장(기본) | 클래스 안 함수 위 | 함수를 소괄호 `()` 없이 변수처럼 읽게 만드는 실시간 계산기 | 숫자가 실시간 표시되는 계기판 |  

<br><br>

## 🟢 이 전부가 파이썬 기본 내장 기능인가?  

### 🟡 1. 결론: 전부 파이썬 기본 기능이다  
- 외부 프로그램이나 라이브러리를 추가 설치(`pip install`)할 필요가 **단 1개도 없음**.  
- 파이썬(Python 3.7 이상)을 설치하는 순간 컴퓨터 안에 모두 기본으로 장착되어 있음.  

<br><br>

### 🟡 2. 컴퓨터 공학 기준의 3단계 세부 분류  

| 구분 | 대상 | 설명 | 사용 방법 |  
| :--- | :--- | :--- | :--- |
| **언어 자체 문법**<br>(Language Syntax) | `@` (골뱅이) | 파이썬 언어 자체의 기본 문법 규칙 | 키보드로 `@` 기호 입력 |  
| **완전 내장 기능**<br>(Built-in) | `@classmethod`<br>`@property` | 파이썬이 켜지자마자 아무 준비 없이 바로 쓸 수 있는 기본 기능 | `import` 없이 즉시 사용 |  
| **표준 라이브러리**<br>(Standard Library) | `@dataclass` | 파이썬 설치 시 기본 제공되지만, 기본 공구함에서 꺼내 써야 하는 표준 부품 | `from dataclasses import dataclass` 작성 후 사용 |  

<br><br>

### 🟡 3. 파이썬의 철학: 배터리 포함 (Batteries Included)  
- 장난감을 샀을 때 상자 안에 건전지(배터리)가 기본으로 들어있어 즉시 작동하듯, 파이썬은 개발에 필요한 핵심 도구들을 기본 탑재한 상태로 배포됨.  
- 따라서 `models.py`의 모든 기능은 별도의 외부 도구 설치 없이 100% 파이썬 기본 환경에서 완벽하게 동작함.  

<br><br>

## 🟢 왜 이딴 게 만들어져 있는가? (탄생 배경과 과거의 고통)  

초보자 눈에는 복잡한 외계어 같지만, 사실 이것들은 **과거 프로그래머들이 흘린 피눈물과 끔찍한 노가다를 없애기 위해 만든 구원투수**임.  

### 🟡 1. @dataclass가 없던 과거 (지옥의 40줄 노가다)  
- `@dataclass`가 없던 시절에는 거래 데이터 하나를 정의하려면 아래처럼 40줄 넘게 손으로 똑같은 글자를 쳐야 했음.  

```python
# 일반 클래스로 거래 틀을 정의한다.  
class 옛날_Transaction:  
    # 1. 태어날 때 값을 집어넣는 함수를 수동으로 작성한다.  
    def __init__(self, id, type, date, amount, category, memo, tags):  
        # 전달받은 id를 주머니에 넣는다.  
        self.id = id  
        # 전달받은 type을 주머니에 넣는다.  
        self.type = type  
        # 전달받은 date를 주머니에 넣는다.  
        self.date = date  
        # 전달받은 amount를 주머니에 넣는다.  
        self.amount = amount  
        # 전달받은 category를 주머니에 넣는다.  
        self.category = category  
        # 전달받은 memo를 주머니에 넣는다.  
        self.memo = memo  
        # 전달받은 tags를 주머니에 넣는다.  
        self.tags = tags  

    # 2. 화면에 예쁘게 글자로 출력하는 함수를 수동으로 작성한다.  
    def __repr__(self):  
        # 모든 값을 하나하나 글자로 묶어서 돌려준다.  
        return f"Transaction(id={self.id}, amount={self.amount})"  

    # 3. 두 거래가 같은지 비교하는 함수를 수동으로 작성한다.  
    def __eq__(self, other):  
        # 모든 항목이 서로 완전히 같은지 일일이 검사한다.  
        return self.id == other.id and self.amount == other.amount  

    # 4. 값 수정을 막는 자물쇠 코드도 수십 줄 추가로 작성해야 한다.  
```

- 글자 하나만 오타가 나도 몇 시간씩 버그를 찾아 헤매야 했음.  
- **해결책**: 머리 위에 `@dataclass(frozen=True)` 단 한 줄을 얹었더니, 파이썬이 위의 **40줄 노가다 코드를 0초 만에 완벽하게 대신 작성**해 줌.  

<br><br>

### 🟡 2. @property가 없던 과거 (치명적인 금융 사고)  
- 가계부의 잔액(`balance`)을 일반 변수(`self.balance = 5000`)로 만들면 생기는 문제:  
    - 수입이 10만 원 들어왔는데 깜빡하고 `self.balance`를 갱신 안 하면 장부 숫자가 엉망이 됨.  
    - 다른 프로그래머가 실수로 `tx.balance = 0`으로 덮어써 버리면 잔액이 증발함.  
- **해결책**: `@property`를 붙여서 **"밖에서 볼 때는 변수처럼 보이지만, 읽을 때마다 컴퓨터가 실시간으로 수입-지출을 계산해서 안전하게 보여주는 잠금장치"**를 만듦.  

<br><br>

### 🟡 3. @ 기호 자체가 없던 과거 (파이썬 2.3 이전)  
- 골뱅이(`@`) 기호가 도입되기 전에는 함수를 포장하려면 함수 본문이 다 끝난 맨 아래에 따로 적어야 했음.  

```python
# 옛날 방식으로 함수를 정의한다.  
def 인사():  
    # 인사말을 출력한다.  
    print("안녕하세요")  

# 함수가 100줄 뒤에 끝난 맨 밑바닥에 가서야 포장지를 씌운다.  
인사 = 마법_모자(인사)  
```

- 함수 코드가 100줄이면 맨 밑까지 스크롤을 내려보지 않고서는 이 함수가 포장된 줄도 모르고 버그를 냄.  
- **해결책**: 함수 머리 위에 `@마법_모자`를 얹어서 **"이 함수는 마법이 걸린 특별한 함수다!"**라고 1초 만에 알 수 있게 만듦.  

<br><br>

## 🟢 쓰는 방법이 왜 이렇게 어렵게 느껴지는가?  

### 🟡 1. 사람의 뇌와 작동 방식이 다르기 때문임  
- 초보자의 뇌: "코드는 1번 줄부터 아래로 순서대로 차례차례 실행된다."  
- 데코레이터의 방식: "아래에 있는 함수를 통째로 들어 올려서 위의 도구에 집어넣고 감싸서 다시 돌려놓는다."  
- 실행 순서가 위아래로 점프하고 감싸지는 구조(고차 함수)이기 때문에 처음 볼 때 당연히 뇌가 거부감을 느낌.  

<br><br>

### 🟡 2. 위안이 되는 팩트: "직접 만들 필요는 없다"  
- 데코레이터를 **새로 발명해서 직접 만드는 것**은 파이썬 중급자~고급자도 머리를 싸매는 어려운 일임.  
- 하지만 우리는 데코레이터를 만드는 사람이 아니라, **이미 똑똑한 파이썬 개발자들이 만들어 둔 모자를 갖다 쓰는 사람**임.  
- 스마트폰의 내부 전자 회로를 이해할 필요 없이 전원 버튼만 누르면 되듯이, 우리는 3개의 모자 이름과 용도만 외우면 끝임:  
    1. 데이터를 안전하게 묶을 때: `@dataclass(frozen=True)`  
    2. 데이터로 객체를 뚝딱 찍어내는 공장을 만들 때: `@classmethod`  
    3. 실시간으로 계산되고 수정 못 하게 막을 때: `@property`  

<br><br>

## 🟢 초등학생에게 설명하듯이 말하는 요약  

- 이 문법들은 괴롭히려고 만든 게 아니라, **개발자가 피눈물 흘리며 쓰던 40줄짜리 노가다 코드를 1줄로 지워주려고 만든 구원투수**다.  
- 만드는 원리는 복잡하지만, 우리는 **파이썬이 준 3개의 마법 모자를 머리 위에 씌우기만 하면 된다**.  
- 1) 금고 모자 `@dataclass(frozen=True)`, 2) 공장 버튼 모자 `@classmethod`, 3) 계기판 모자 `@property` 딱 3개만 알면 된다.
